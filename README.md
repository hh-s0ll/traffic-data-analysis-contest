# 부르지 않아도 오는 똑버스
### 경기도 의료이동 상대적 취약지역 탐지와 병원 예약 연계 공동배차의 탄소 감축 조건 탐색

숲과나눔 × 한겨레 **「AI와 함께하는 교통문제 해결을 위한 데이터 분석 공모전」** 출품용 저장소입니다.  
실제 공개데이터를 이용한 분석 코드·결과, 정책 시뮬레이션, 분석보고서, 결과 시연용 웹 데모를 함께 제공합니다.

> **중요 — 실제 분석과 데모 데이터는 구분되어 있습니다.**  
> `analysis/`의 산출물은 공개데이터를 이용해 재현 가능한 분석 결과입니다. 반면 `src/mock/`의 값은 화면 동작과 정책 시나리오를 보여주기 위한 **가상 데이터**이며 실제 통계·예약 정보가 아닙니다.

## 연구 질문

이 프로젝트는 “똑버스를 늘리면 무조건 이동권과 탄소 문제가 함께 해결된다”는 전제를 두지 않고 다음 세 질문을 데이터로 확인합니다.

1. **의료이동이 상대적으로 가장 불리한 지역은 어디인가?**
2. **병원 예약 연계 공동배차는 어떤 조건에서 탄소를 줄일 수 있는가?**
3. **그 조건을 시군별 운영 기준과 정책으로 어떻게 바꿀 수 있는가?**

## 핵심 결과

- 경기도 읍·면·동 **600곳**을 비교해 상대적 의료이동 취약지역 **120곳**, 그중 **고령 고립형 68곳**을 도출했습니다.
- 고령 고립형은 부트스트랩 재학습과 다른 군집 방법에서도 비교적 안정적으로 유지됐습니다.
- 취약 읍면이 2곳 이상인 **15개 시군 × 400개 조건 = 6,000개 운영 시나리오**를 만들고 XGBoost·랜덤포레스트 대리모델을 비교했습니다.
- XGBoost는 시군 단위 교차검증에서 주요 운영 성과를 **R² 0.66~0.91** 수준으로 재현했습니다. 이 정확도는 현실 수요 예측 정확도가 아니라 **시뮬레이션을 재현하는 대리모델의 성능**입니다.
- 시뮬레이션에서는 지역 특성만큼이나 **배차 규칙, 차량 전환율, 차종·좌석 조건**이 탄소와 수송률을 크게 좌우했습니다.
- 현행 가정(경유 7인승·승객 6석·전환율 21.3%)에서는 15개 시군 모두 손익분기 기준 공동배차가 활성화되지 않았고, 전기차·승객 11석·전환율 40% 조건에서는 여러 시군에서 수송률과 탄소 성과가 개선되는 것으로 계산됐습니다. 이는 **정책 시뮬레이션 결과**이며 실제 운영 효과를 의미하지 않습니다.

자세한 수치와 해석은 [분석보고서](report/팀명_분석보고서_미리보기.pdf)와 [분석 재현 안내](analysis/README.md)를 참고해 주세요.

## 분석 구조

### 1단계 — 실제 공개데이터 기반 실증 분석

- SGIS 행정구역 경계·성연령별 인구
- 건강보험심사평가원 병원·진료과목 정보
- 국토교통부 전국 버스정류장 위치정보
- 고령 비율, 병원 접근성, 정류장 공급 지표 생성
- 상대적 취약도 지수 산출
- K-평균 군집화 및 가우시안 혼합·계층 군집 비교
- 부트스트랩 안정성, 랜덤포레스트 대리모델, PCA 기반 검증

### 2단계 — 정책 시뮬레이션 및 AI 대리모델

- 공동배차의 탄소 손익분기 조건 계산
- 연천군 가상 예약 수요 몬테카를로 시뮬레이션
- 15개 시군으로 운영 조건 확장
- 6,000개 시나리오 데이터셋 생성
- XGBoost·랜덤포레스트 비교 및 시군 단위 GroupKFold 검증
- SHAP으로 운영 성과에 영향을 주는 요인 설명
- 대리모델로 후보 조건을 탐색한 뒤 직접 시뮬레이션으로 최종 판단 확인

## 실제 분석 재현

원자료는 약 300MB로 저장소에 포함하지 않았습니다. 공개 원자료의 다운로드 방법과 출처는 [analysis/README.md](analysis/README.md)에 정리되어 있습니다.

Windows 기준으로 다음 순서로 전체 분석을 다시 실행할 수 있습니다.

```bash
cd analysis
python -m venv .venv
.venv/Scripts/python -m pip install -r requirements.txt
.venv/Scripts/python src/s00_download.py
.venv/Scripts/python src/run_all.py
```

분석에 사용한 난수 시드는 코드에 고정되어 있으며, 동일한 입력에서는 같은 분석 결과가 생성되도록 구성했습니다.

## 웹 데모 실행

웹 데모는 분석 결과를 설명하고 정책 시나리오를 시연하기 위한 React/Vite 인터페이스입니다.

```bash
npm install
npm run dev        # http://localhost:5173
npm run build      # 타입 검사 + 배포용 빌드
npm run typecheck  # 타입 검사
```

Node.js 20 이상을 권장합니다.

### 데모 화면

| 경로 | 화면 | 역할 |
| --- | --- | --- |
| `#/overview` | 개요 | 문제 정의와 서비스 흐름 |
| `#/data` | 데이터와 방법 | 데이터·분석 과정·AI 활용 |
| `#/map` | 취약지역 지도 | 취약지역 결과를 시각적으로 설명 |
| `#/dispatch` | 공동배차 시뮬레이터 | 예약 묶음과 배차 조건 시연 |
| `#/carbon` | 탄소 손익분기 | 차종·전환율·합승 인원 조건 비교 |
| `#/policy` | 정책 제안 | 분석 결과를 운영·정책 제안으로 연결 |

현재 웹 데모의 `src/mock/` 데이터는 시연용입니다. **보고서의 실증 결과는 `analysis/`의 산출물을 기준으로 확인해야 합니다.**

## 주요 분석 가정과 한계

- 병원 접근거리는 실제 도로 경로가 아니라 **직선거리 × 도로 보정계수**로 근사했습니다.
- 실제 똑버스 병원 예약·운행 데이터는 공개되지 않아 공동배차 수요는 **가상 수요 시뮬레이션**으로 분석했습니다.
- 차량 전환율 21.3%는 수원시정연구원 똑버스 이용자 조사를 참고한 보수 가정이며, 대상 지역 고령자의 실측 전환율은 아닙니다.
- 기본·적극 전환율과 일부 운영 조건은 가정값이므로 민감도·불확실성 분석을 함께 제시했습니다.
- 대리모델은 시뮬레이션 결과를 빠르게 탐색하기 위한 도구이며 실제 현장 수요를 직접 예측하는 모델이 아닙니다.
- 최종 정책 도입 전에는 실제 예약·이전 이동수단·동승 여부·차량 운행 데이터를 이용한 현장 검증이 필요합니다.

## AI 활용

AI는 **분석 방법**과 **작업 보조**를 구분해 사용했습니다.

- 분석 방법: K-평균, 가우시안 혼합, 계층 군집, 랜덤포레스트, XGBoost, SHAP
- 생성형 AI 보조: 공개데이터 탐색, 코드·문서 초안, 검토 및 저장소 정리
- 최종 수치와 결과는 팀원이 코드를 재실행하고 산출물과 대조하는 방식으로 확인

자세한 공개 내용은 [AI 활용 내역](docs/AI활용내역_데모.md)에 정리했습니다.

## 기술 스택

- **Analysis:** Python, pandas, NumPy, GeoPandas, scikit-learn, XGBoost, SHAP, Matplotlib
- **Web demo:** React, TypeScript, Vite, Recharts
- **Report:** JavaScript 기반 DOCX 생성 스크립트 + PDF 미리보기

## 데이터·개인정보 원칙

- 실제 분석은 공개데이터만 사용합니다.
- 웹 데모의 예약 데이터는 가상 데이터이며 개인 식별 정보를 포함하지 않습니다.
- 이름, 병명, 진료과, 연락처 등 개인 식별 가능 정보는 데이터 계약에 포함하지 않습니다.
- 가상 데이터와 실증 분석 결과를 구분해 표시하고, 가상 값을 실제 분석 근거로 사용하지 않습니다.
