# AI 활용 내역

이 문서는 숲과나눔 × 한겨레 「AI와 함께하는 교통문제 해결을 위한 데이터 분석 공모전」 제출 및 저장소 공개를 위해 프로젝트 수행 과정의 AI 활용 범위와 검증 원칙을 정리한 기록입니다.

## 1. 활용한 AI 도구와 역할

| 구분 | 도구·기법 | 활용 범위 | 최종 판단 |
| --- | --- | --- | --- |
| 생성형 AI | Anthropic Claude Code | 공개데이터 탐색, Python 코드 및 보고서 초안 작성 보조 | 팀원 검토·재실행 |
| 생성형 AI | OpenAI ChatGPT | 아이디어·분석 방향 검토, 코드·README 점검, GitHub 저장소 구성 및 문서 정리 보조 | 팀원 검토 |
| 분석용 ML | K-평균, 가우시안 혼합, 계층 군집, 랜덤포레스트, XGBoost, SHAP 등 | 취약 유형 발견·검증, 시뮬레이션 대리모델, 요인 설명 | 팀원 해석·검증 |

> 생성형 AI와 분석용 머신러닝 모델은 구분해 사용했습니다. 생성형 AI가 실제 분석 결과의 수치나 최종 정책 결론을 임의로 생성하도록 사용하지 않았습니다.

## 2. 생성형 AI 활용 범위

- 공모전 주제와 문제 정의를 구체화하고 아이디어의 논리 구조를 점검
- 공개데이터 후보와 분석 단계, 정책 시뮬레이션 구조를 정리
- Python·TypeScript 코드의 초안 작성 및 오류 가능성 점검
- 분석보고서·README·GitHub 폴더 구조와 재현 절차 정리
- 실제 분석값과 가상 데모값이 혼동되지 않도록 표현 검토

## 3. 사람이 직접 확인한 부분

- 공개데이터의 출처, 기준시점, 이용 가능 여부
- 전처리 기준과 분석 변수의 최종 선택
- 코드 실행 여부와 산출물 생성 여부
- 표·그림·분석 결과의 주요 수치
- 모델 비교와 정책 해석의 최종 채택 여부
- 보고서에 들어가는 최종 문장과 근거 자료
- 공모전 제출 규정 및 공개 범위

## 4. 실제 분석과 웹 데모의 구분

- `analysis/`: 실제 공개데이터를 이용한 분석 코드와 산출물
- `src/mock/`: 화면 동작과 정책 시나리오를 보여주기 위한 가상 데이터
- `analysis/output/`: 보고서에 사용되는 실제 분석 표·그림

웹 데모의 가상 값은 실제 통계나 실제 병원 예약 정보가 아니며, 실제 분석 결과인 것처럼 보고서 근거로 사용하지 않습니다.

## 5. 검증 원칙

1. AI가 제안한 사실·수치는 공개 원자료 또는 분석 산출물과 대조합니다.
2. 출처를 확인할 수 없는 수치는 실증 결과로 사용하지 않습니다.
3. 코드 수정 후에는 분석을 다시 실행하고 주요 표·그림을 확인합니다.
4. 가상 시나리오와 실증 분석 결과를 문서와 화면에서 구분해 표시합니다.
5. 대리모델의 예측은 직접 시뮬레이션과 다시 대조해 최종 판단에 사용합니다.
6. 최종 제출물의 내용과 책임은 팀원에게 있습니다.

## 6. 주요 프롬프트 유형

프로젝트 진행 과정에서는 다음과 같은 유형의 요청을 사용했습니다.

- “로그인 없이 받을 수 있는 공개데이터로 분석 가능한 구조를 정리해줘.”
- “현재 공모전의 평가 방향과 문제 정의에 맞는지 검토해줘.”
- “분석 결과와 정책 시뮬레이션을 혼동하지 않도록 표현을 점검해줘.”
- “코드를 재실행했을 때 같은 결과가 나오도록 재현 절차를 점검해줘.”
- “보고서 수치와 저장소 산출물이 일치하는지 확인할 항목을 정리해줘.”
- “검토 의견을 반영해 분석 및 문서 구조를 다시 점검해줘.”

생성형 AI의 응답은 초안·검토 자료로 활용했으며, 팀원이 검증한 뒤 최종 결과물에 반영했습니다.
