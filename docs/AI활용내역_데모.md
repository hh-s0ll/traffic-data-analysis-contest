# AI 활용 내역

이 문서는 숲과나눔 × 한겨레 「AI와 함께하는 교통문제 해결을 위한 데이터 분석 공모전」 제출 및 저장소 공개를 위해, 프로젝트 수행 과정에서의 AI 활용 범위와 검증 원칙을 정리한 기록입니다.

## 1. 활용한 AI 도구

| 도구 | 활용 범위 | 최종 판단 주체 |
| --- | --- | --- |
| OpenAI ChatGPT | 아이디어 구체화, 분석·정책 방향 검토, 코드 및 README 점검, 문서 구조 정리, GitHub 저장소 구성 보조 | 팀원 |
| 분석 모델·설명 도구 | K-평균, 가우시안 혼합, 계층 군집, 랜덤포레스트, XGBoost, SHAP 등을 실제 공개데이터 분석 및 결과 해석에 활용 | 팀원 |

> 생성형 AI와 분석용 머신러닝 모델은 구분해 사용했습니다. 생성형 AI가 실제 분석 결과의 수치나 결론을 임의로 생성하도록 사용하지 않았습니다.

## 2. 생성형 AI 활용 범위

생성형 AI는 다음과 같은 보조 작업에 활용했습니다.

- 공모전 주제와 문제 정의를 구체화하고 아이디어의 논리 구조를 점검
- 공개데이터 활용 방향, 분석 단계, 정책 시뮬레이션 구조를 정리
- 분석 코드와 웹 데모 코드의 오류 가능성 및 설명 문구를 검토
- README, 보고서 구성, GitHub 폴더 구조와 재현 절차를 정리
- 보고서와 저장소에서 실제 분석값과 가상 데모값을 명확히 구분하도록 표현을 점검

## 3. AI를 사용하지 않은 최종 판단 영역

다음 항목은 생성형 AI의 답변을 그대로 채택하지 않고 팀원이 직접 확인·판단했습니다.

- 공개데이터의 출처, 기준시점, 이용 가능 여부
- 전처리 기준과 분석 변수의 최종 선택
- 실제 분석 코드 실행과 산출물 확인
- 표·그림·분석 결과의 수치 검산
- 정책 제안의 최종 채택 여부
- 보고서에 들어가는 최종 문장과 근거 자료
- 공모전 제출 규정 준수 여부

## 4. 실제 분석과 웹 데모의 구분

이 저장소의 `analysis/` 폴더는 실제 공개데이터를 이용한 분석 코드와 산출물입니다.

반면 `src/`의 프론트엔드 데모에는 화면 동작과 정책 시나리오를 보여주기 위한 가상 데이터가 포함되어 있습니다. 가상 데이터는 실제 통계나 실제 병원 예약 정보가 아니며, 실제 분석 결과인 것처럼 보고서 근거로 사용하지 않습니다.

실제 분석 결과는 `analysis/data/processed/`, `analysis/output/tables/`, `analysis/output/figures/`의 산출물과 분석보고서를 기준으로 확인합니다.

## 5. 검증 원칙

1. AI가 제안한 사실·수치는 공개 원자료 또는 분석 산출물과 대조합니다.
2. 출처를 확인할 수 없는 수치는 실제 분석 결과로 사용하지 않습니다.
3. 코드 수정 후에는 분석을 다시 실행하고 주요 표·그림을 확인합니다.
4. 가상 시나리오와 실증 분석 결과를 화면과 문서에서 구분해 표시합니다.
5. 최종 제출물의 내용과 책임은 팀원에게 있습니다.

## 6. 주요 프롬프트 유형

프로젝트 진행 과정에서 다음과 같은 형태의 요청을 주로 사용했습니다.

- "현재 공모전의 평가 방향에 맞는지 아이디어를 검토해줘."
- "공개데이터로 검증 가능한 분석 단계와 필요한 변수를 정리해줘."
- "분석 결과와 정책 시뮬레이션을 혼동하지 않도록 표현을 점검해줘."
- "코드와 README를 보고 재현에 필요한 설명이 빠졌는지 확인해줘."
- "보고서의 수치와 저장소 산출물이 일치하는지 확인할 항목을 정리해줘."

프롬프트 결과는 초안과 검토 자료로 활용했으며, 그대로 자동 제출하지 않았습니다.
